# 让 Agent 动手前先问一声

## 为什么需要审批

Agent 越自主，越可能做出不可逆的动作：删错文件、发错邮件、把草稿发布出去。
全自动和全人工之间需要一块可控的中间地带——
**在执行前暂停，等人批准、修改或拒绝。**

## 按风险分四层

| 层 | 典型工具 | 策略 |
|---|---|---|
| 高 | 删除、覆盖写入、对外发送、上线 | 批准 / 改参数 / 拒绝 |
| 中 | 一般写入、外部调用 | 批准 / 拒绝 |
| 低 | 读取、搜索、列目录 | 不拦 |
| 输入型 | 向人提问 | 让人直接给出答案 |

高风险层不要开放"人代替工具返回结果"这个决策——
它会被模型当成一次成功的工具返回，从而误以为动作真的执行了。
不执行就用明确的拒绝，并把原因说清楚。

## 恢复要靠三样东西

中断不是弹个确认框就完了，它需要能把工作流在任意时间跨度后接上：

1. **状态持久化**——中断现场必须存在，否则没人知道停在哪
2. **同一个会话标识**——恢复要回到原来那条线，不是新开一条
3. **决策与动作一一对应**——一次中断里打包了多个动作时，顺序不能错

## 一条反直觉的规则

恢复执行时，暂停点所在的节点会**从头重放**，而不是从暂停那一行继续。
所以暂停之前的副作用必须能重复执行——写日志用 upsert，
发消息先做幂等键，总之别让"重放一次"变成"多记一笔"。

相应地，也不能用笼统的异常捕获把暂停异常吞掉，
那会让流程卡死在原地而不报错。
