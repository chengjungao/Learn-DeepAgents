# 搜索平台的五代演进

## 一代：单体 Solr

最早只有一台 Solr 撑全站检索。索引全量重建，每天凌晨跑一次。
瓶颈很明确：重建期间查询会抖，且单机索引容量有天花板。

## 二代：分布式

把索引切成多个 shard 分散到多台机器，用 ZooKeeper 管集群状态。
解决了容量问题，但带来了新的麻烦：跨 shard 的排序与聚合变得昂贵，
深分页开始出现超时。

## 三代：微服务化

检索被拆成独立服务，与商品、库存等域解耦，各自独立扩缩容。
这一代最大的收益不是性能，而是**变更半径**变小了——
改召回逻辑不再需要整个搜索应用重新发布。

## 四代：双塔多路召回

从"单路召回 + 规则排序"改成"多路召回 + 统一粗排"。
典型组合：关键词召回、向量召回、类目/品牌强规则召回。
双塔模型负责把 query 和 item 映射到同一向量空间。

多路召回的关键工程问题不是模型，而是**打分的可比性**：
不同召回路的分数分布完全不同，必须统一到可比的量纲再做融合。

## 五代：AI 搜索

在四代基础上引入大模型做理解与编排：
- query 理解从"分词 + 同义词"升级为意图解析与改写
- 排序阶段引入 LLM 做相关性重排与理由生成
- 编排层开始用 Agent 串起多路召回与后处理

这一代的成本结构和前四代完全不同：不再是纯 CPU/IO 密集，
而是"GPU 推理 + 缓存命中率"的平衡问题。
