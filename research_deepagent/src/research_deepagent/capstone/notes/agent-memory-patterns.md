# Agent 的记忆该放哪儿

## 两类记忆，别混着存

短期记忆活在单个对话线程里，换 thread 就没了；长期记忆要跨对话，
按用户或 Agent 隔离。判断标准很简单：**这条信息下个对话还需要吗。**

## 三种存放位置的取舍

- **状态内（图 state）**：一次对话的草稿纸，随对话结束消失。适合中间产物。
- **持久存储（Store）**：按 namespace 隔离，跨对话保留。适合偏好、长期结论。
- **程序性记忆（Skills）**：不是数据而是"怎么做"，按需加载。适合格式规范和操作流程。

三者不是互斥的，是**同时用**：草稿走 state，偏好走 Store，规范走 Skills。

## 一个容易踩的坑

读取配置不等于写入约定。声明"从这里加载记忆"不会顺带建好这个文件，
也不会约束模型往哪儿写。缺文件时多数框架是静默跳过——
不报错，只是那份记忆不存在。

所以要么在初始化时预置文件，要么在提示词里把写入路径写死。

## 验证要看三层，不是一层

1. 存储里有文件吗（数据到位）
2. 内容进了模型输入吗（路由到位）
3. 产出真的遵守了它吗（生效）

只查第一层，一个"文件躺着没人读"的 bug 也能全绿。

验证第 2 层有个细节：系统提示词通常不在对话消息列表里，
要看真正发给模型的请求。验证第 3 层必须**换一个新线程**——
同一线程继续对话会复用已加载的内容，那证明不了跨对话。
